# MAX Web Chat — веб-чат для мессенджера MAX на GREEN-API

Минималистичный веб-клиент для отправки и получения текстовых сообщений в [MAX](https://max.ru)
через сервис [GREEN-API](https://green-api.com/max). Интерфейс повторяет внешний вид
[web.max.ru](https://web.max.ru): список чатов слева, переписка справа.

## Возможности

- Вход по учётным данным инстанса GREEN-API (`idInstance`, `apiTokenInstance`) с проверкой
  состояния инстанса через `getStateInstance`.
- Создание чата по номеру телефона получателя (РФ `+7` и РБ `+375`).
- Отправка текстовых сообщений методом [SendMessage](https://green-api.com/v3/docs/api/sending/SendMessage/).
- Получение сообщений по технологии [HTTP API](https://green-api.com/v3/docs/api/receiving/technology-http-api/)
  (`ReceiveNotification` + `DeleteNotification`, long polling).
- Статусы исходящих сообщений: отправляется → отправлено → доставлено → прочитано, а также
  «не отправлено» с повторной отправкой.
- Входящие сообщения из новых чатов появляются в списке автоматически, со счётчиком непрочитанных.
- История переписки сохраняется локально и переживает перезагрузку страницы.
- Светлая и тёмная темы (по настройкам системы), адаптивная вёрстка для мобильных устройств.
- Доступность: семантическая разметка, подписи для скринридеров, управление с клавиатуры.

## Быстрый старт

Требуется Node.js 20.19+ (см. `.nvmrc`).

```bash
npm install
npm run dev
```

Откройте http://localhost:5173 и введите `idInstance` и `apiTokenInstance` из
[личного кабинета GREEN-API](https://console.green-api.com).

Production-сборка:

```bash
npm run build     # результат в dist/, можно разместить на любом статическом хостинге
npm run preview   # локальный просмотр сборки
```

## Настройка инстанса GREEN-API

1. Создайте инстанс MAX в личном кабинете и авторизуйте его по QR-коду
   (в приложении MAX: «Профиль» → «Устройства» → «Войти по QR-коду»).
2. В настройках инстанса **оставьте пустым `webhookUrl`**: при заданном URL метод
   `ReceiveNotification` возвращает ошибку.
3. Включите уведомления:
   - «Получать уведомления о входящих сообщениях и файлах» (`incomingWebhook`) — обязательно, без
     этого ответы не придут;
   - «Получать уведомления о статусах отправленных сообщений» (`outgoingWebhook`) — для галочек
     «доставлено»/«прочитано»;
   - «Получать уведомления о сообщениях, отправленных с телефона» (`outgoingMessageWebhook`) —
     чтобы видеть в чате сообщения, написанные с телефона.

Адрес API по умолчанию вычисляется из `idInstance` (`https://{первые 4 цифры}.api.green-api.com`).
Если в личном кабинете указан другой `apiUrl`, задайте его в разделе «Дополнительно» на экране входа.

## Сценарий проверки

1. Войдите с данными инстанса.
2. Введите номер телефона получателя и нажмите «+»: будет создан новый чат.
3. Напишите сообщение и отправьте его (Enter, Shift+Enter — перенос строки).
4. Ответьте на сообщение в приложении MAX на телефоне получателя.
5. Ответ появится в чате в течение нескольких секунд.

## Архитектура

```
src/
├── api/             # Взаимодействие с GREEN-API
│   ├── greenApiClient.ts      # Типизированный HTTP-клиент: таймауты, отмена, разбор ошибок
│   ├── notificationPoller.ts  # Цикл ReceiveNotification → обработка → DeleteNotification
│   ├── errors.ts              # GreenApiError и человекочитаемые сообщения
│   └── types.ts               # DTO запросов, ответов и вебхуков
├── domain/          # Чистая бизнес-логика без React
│   ├── notifications.ts       # Вебхук → доменное событие (сообщение / статус)
│   ├── phone.ts               # Нормализация, валидация и форматирование номеров
│   └── chat.ts, types.ts
├── store/           # Состояние приложения
│   ├── chatReducer.ts         # Чистый редьюсер: чаты, сообщения, статусы
│   ├── ChatProvider.tsx       # Связывает API, цикл уведомлений и состояние
│   ├── chatContext.ts         # Контексты и хуки доступа
│   └── storage.ts             # Сохранение в localStorage / sessionStorage
├── features/        # UI по функциональным областям
│   ├── auth/                  # Экран входа
│   ├── chats/                 # Боковая панель: новый чат, список чатов
│   └── conversation/          # Окно переписки: лента, пузыри, поле ввода
├── components/      # Переиспользуемые UI-компоненты (аватар, иконки, логотип)
├── app/             # Корневой компонент, раскладка, Error Boundary
└── lib/             # Утилиты форматирования дат
```

Слои зависят только «вниз»: `features` → `store` → `domain` / `api`. Бизнес-логика (`domain`,
`chatReducer`, `notificationPoller`) не зависит от React и покрыта юнит-тестами, а основной
пользовательский сценарий проверяется интеграционным тестом на фейковом клиенте API.

### Ключевые решения

- **Номер телефона → `chatId` через `CheckAccount`.** В MAX входящие уведомления приходят с
  числовым `chatId`, а не с номером телефона. Поэтому при создании чата номер сначала
  разрешается в `chatId` (как [рекомендует документация](https://green-api.com/v3/docs/api/chat-id/)),
  иначе ответ собеседника нельзя сопоставить с открытым чатом. Заодно пользователь сразу узнаёт,
  если у номера нет аккаунта MAX.
- **Надёжная очередь уведомлений.** Каждое уведомление подтверждается `DeleteNotification`, даже
  если оно не относится к чату (статус инстанса, медиа), иначе FIFO-очередь «застрянет». Обработка
  идемпотентна: повторно доставленное уведомление не создаёт дубликат сообщения.
- **Long polling** с `receiveTimeout=20` вместо частого опроса: меньше запросов при той же скорости
  доставки. При сетевых ошибках повторы идут с нарастающей задержкой (1 → 30 с), состояние
  соединения видно в шапке.
- **Оптимистичная отправка.** Сообщение появляется сразу со статусом «отправляется», затем получает
  серверный `idMessage`. Учтена гонка, когда вебхук `outgoingAPIMessageReceived` приходит раньше
  HTTP-ответа: дубликата не будет. Статусы никогда не «откатываются» (прочитано → доставлено), даже
  если вебхуки пришли не по порядку.
- **Хранение данных.** Токен хранится в `sessionStorage` (живёт до закрытия вкладки), история
  чатов — в `localStorage` отдельно для каждого инстанса, не более 500 сообщений на чат.
- **Без лишних зависимостей.** Только React: состояние на `useReducer` + Context, стили на CSS
  Modules с дизайн-токенами в CSS-переменных.

## Ограничения

- По условиям задания поддерживаются только текстовые сообщения; медиа и прочие типы
  игнорируются.
- MAX позволяет обращаться по номеру телефона только к номерам РФ и РБ.
- Учётные данные используются прямо в браузере, так как задание не предусматривает бэкенд. Для
  production стоит проксировать запросы через свой сервер, чтобы не раскрывать `apiTokenInstance`.
- История формируется из очереди уведомлений (GREEN-API хранит их 24 часа); более старая переписка
  из MAX не подгружается.
